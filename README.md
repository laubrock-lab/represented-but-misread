# latent-detection

**Do language models know more than they say?** This project separates sensitivity
from response bias when language models judge whether a German text was written by
a human or generated by an AI, using signal detection theory (SDT) at both the
output level and the representational level.

## Background

In an experimental psychology practicum (lab course, University of Potsdam, summer
2026), human participants and frontier LLMs judged the same German texts as
"Mensch" or "KI". In one-shot judging, all four LLMs answered almost exclusively
"Mensch" (d′ ≈ 0, c > 2). With forced reasoning and base-rate information, one
model reached d′ ≈ 1.4, which suggests that discriminating information is present
but not expressed in the default answer.

This repository tests that idea with open-weight models, where the internals are
accessible:

1. **Base vs. instruct (output level).** The log-odds `dv = log P("KI") − log P("Mensch")`
   give a continuous decision variable per text. From it we get the ROC, d′ (from
   the AUC) and the criterion c. Comparing base and instruction-tuned weights of
   the same family, with the same prompt, isolates the effect of post-training on
   sensitivity and bias.
2. **Linear probes (representation level).** Probes on the residual stream, layer
   by layer, give a "representational d′". If the probe's d′ is high while the
   output's d′ is low, the model represents the difference but doesn't report it,
   a dissociation like blindsight.
3. **Steering (optional).** Adding the probe direction to the residual stream
   should shift c while leaving d′ unchanged.

## Data policy

The stimulus texts are **not** part of this repository and never will be:

- `data/` and `outputs/` are gitignored. Texts, per-text judgments and activations
  stay local.
- The journalism corpus is confidential. It is processed **only locally** with
  open-weight models, with no API calls.
- Scripts never print text content. The sanity output shows answer tokens only.

## Usage

```bash
# 1. export texts from the internal lab course repository to data/ (local only)
python prepare_texts.py                     # set LABCOURSE_DIR if the repo moved

# 2. smoke test (first 10 texts -> outputs/chat/smoke/)
python judge_logits.py --texts data/texts_chat.parquet --preset gemma3-4b --limit 10

# 3. full run: base raw, instruct raw, instruct chat x both answer orders
python judge_logits.py --texts data/texts_chat.parquet --preset gemma3-4b

# 4. SDT summary with grouped-bootstrap CIs
python sdt_summary.py outputs/chat
```

Model presets live in `config.py` (`gemma3-4b`, `gemma3-12b`, `llama31-8b`,
`qwen25-7b`). Any base/instruct pair can be given with `--base-id/--instruct-id`.

### Reading the output

- `p_mass` = P(Mensch) + P(KI) for the next token. Low values (base models often
  predict a newline first) don't bias `dv`, which is the log-odds *conditional*
  on answering at all. Values near 0 mean the prompt isn't working for that model.
- Small models show strong **answer-order bias**: they pick whichever option is
  mentioned first or last. Use the `avg` rows, which average `dv` over both orders.
- `c0 > 0` means a conservative bias toward "Mensch", the sign convention of the
  lab course analyses.
